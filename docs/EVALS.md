# Слепой тест моделей

Скрипты в `evals/` сравнивают модели на написании сцен так, чтобы читающий не знал, какая модель что написала.

## Как это работает

`evals/blind_ab.py` для каждого кейса генерирует сцену несколькими моделями тем же путём, что и бот: системный промпт чата, канон из `get_relevant_facts`, `build_messages`, стриминг. Факты подбираются один раз на кейс, поэтому разницу дают только модели.

Судья (Sonnet) читает список фактов и сцену и возвращает JSON: список противоречий канону и сколько фактов отражено в тексте. Противоречием считается только прямое нарушение факта, а не отсутствие факта и не выдуманная деталь, которой канон не противоречит. Длина считается автоматически (слова по `\w+`), границы задаются в кейсе.

Сцены перемешиваются под буквами A, B, C (порядок зависит от `--seed` и номера кейса) и уходят автору в Telegram. Какая буква какой модели, лежит в `key.json` рядом с прогоном.

В репозитории хранятся только скрипты и `evals/cases.example.jsonl` с нейтральными запросами. Тексты сцен, факты и результаты прогонов в репозиторий не попадают: `eval_runs/` и `evals/cases.local.jsonl` в `.gitignore`.

## Запуск

В контейнере бота (там `.env`, системный промпт и доступ к БД):

```bash
docker exec klgpff-bot-klgpff-bot-1 python evals/blind_ab.py --user-id <id>
```

Параметры:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--user-id` | обязателен | Чьи факты и промпт брать |
| `--cases` | `evals/cases.local.jsonl`, если его нет, то `evals/cases.example.jsonl` | Файл с кейсами |
| `--models` | `haiku,sonnet,opus` | Какие модели сравнивать |
| `--seed` | 7 | Для порядка букв |
| `--workers` | 3 | Сколько кейсов идёт параллельно |
| `--no-send` | выключен | Не отправлять тексты в Telegram |

Формат кейса, одна JSON-строка на кейс: `{"id": "a", "prompt": "...", "min_words": 1000, "max_words": 450}`. Границы необязательны.

Папка `evals/` копируется в образ при сборке, поэтому свой `cases.local.jsonl`, положенный рядом с кодом на хосте, контейнер не увидит. Положите файл в `eval_runs/` (она примонтирована) и укажите `--cases eval_runs/имя.jsonl`.

Результат пишется в `eval_runs/<дата-время>/`: `run.json` (тексты и метрики) и `key.json`. В конце скрипт печатает строку «прогон сохранён: <папка>, стоимость ≈ $...». Тексты в stdout не попадают.

Стоимость: полный прогон (8 кейсов, три модели, сцены от 1000 слов) стоил $2.98, урезанный (3 кейса до 400 слов, две модели) $0.37. Судья читает все факты и составляет заметную часть: во втором прогоне $0.142 из $0.37. Ориентир на один прогон от $0.4 до $3.

Известная мелочь: вступительное сообщение в Telegram всегда пишет «по 3 варианта» и показывает пример из трёх букв, даже если моделей две (текст в `send_pack`).

## Оценка

```bash
docker exec klgpff-bot-klgpff-bot-1 python evals/blind_score.py <папка> 1ACB 2CAB ...
```

Каждый токен это номер кейса и буквы от лучшего к худшему. Принимаются две и три буквы, кириллические А, В, С заменяются на латинские. Скрипт печатает таблицу (победы, средний ранг, противоречий канону на сцену, доля сцен в объёме, цена за сцену), без текстов, и пишет её же в `RESULTS.md` в папке прогона.

## Результаты

### Прогон 1, 14.11.2026

8 кейсов из `cases.example.jsonl`, модели haiku, sonnet, opus.

| Модель | Побед | Средний ранг | Цена за сцену |
|---|---|---|---|
| opus | 5 из 8 | 1.38 | $0.207 |
| haiku | 2 из 8 | 2.12 | $0.003 |
| sonnet | 1 из 8 | 2.50 | $0.085 |

Весь прогон стоил $2.98.

Выдача фактов была неполной: в промпт попадало 30 из 132 фактов (поиск по одному запросу, `FACTS_FULL_LIMIT` тогда был 0), а из восьми ключевых фактов (имена, город, внешность) в выдачу попадало от 0 до 3. По наблюдению автора, при чтении модели писали чужие имена и другой город (в данных скрипта это не зафиксировано).

Колонка «противоречий канону» в этом прогоне несравнима: судья видел тот же неполный список. Относительное сравнение моделей честное, потому что канон у всех был одинаково неполным. Абсолютное качество по этому прогону оценить нельзя.

Исправление: `FACTS_FULL_LIMIT=150`, модель и судья получают все 132 факта.

### Прогон 2, 14.11.2026

3 кейса до 400 слов, модели haiku и opus, полный канон.

| Модель | Побед | Средний ранг | Противоречий канону на сцену | В объёме | Цена за сцену |
|---|---|---|---|---|---|
| opus | 3 из 3 | 1.00 | 0.00 | 100% | $0.072 |
| haiku | 0 из 3 | 2.00 | 0.33 | 100% | $0.003 |

Весь прогон стоил $0.37, из них судья $0.142. Все шесть сцен уложились в лимит слов, везде `stop_reason=end_turn`.

### Оговорки

- Оценивал один человек, автор бота.
- Кейсов три. Три победы из трёх при двух вариантах случайно получаются примерно в 12% случаев.
- Судья сам модель (Sonnet), противоречие на три сцены (0.33) слишком мало, чтобы считать закономерностью.
- Тест покрывает только написание новой сцены. Переписывание и продолжение не проверялись.
- Sonnet на полном каноне не тестировали.
- Цены в таблицах считаются по `PRICING` из кода.

### Вывод

Для сцен выбран Opus 5.5, он стал режимом по умолчанию. Это предпочтение автора на малой выборке, а не строгая оценка.
